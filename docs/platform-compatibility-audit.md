# YouTube、哔哩哔哩与小宇宙兼容性复查

复查日期：2026-11-01。本次针对 Margin 书架和阅读页，沿用已接入的两个真实样例；报告已去除具体来源信息。改动已在本地应用；代码同步 GitHub 不代表已部署线上。

用户看到 Learning 在新平台上表现不一致，确实有代码和显示上的缺口。不过，学习状态的存储与筛选本身没有绑定 YouTube。下面分别记录发现的问题、验证结果和仍有的平台差异。

## 已修复的问题

| 问题 | 原来的表现 | 修复后的行为 |
| --- | --- | --- |
| 书架隐藏学习状态 | 卡片用“作者或学习状态”显示信息；有作者时就看不到 Learning 或 Completed | 平台、作者和学习状态分别显示，三个平台一致 |
| 自动 Learning 依赖字幕 | 播放时间回调先检查字幕；字幕尚未加载时，不保存播放进度，也不标记 Learning | 播放进度和学习状态独立于字幕加载；字幕到达后再同步段落 |
| 自动更新可能覆盖手动完成 | 客户端根据旧状态直接提交 `status: learning`，遇到另一窗口刚标记完成时可能覆盖 | 播放提交 `activity: playback`，数据库只将 `new` 改为 `learning`，保留手动 Completed |
| 中文章节沿用英文提示 | AI 章节提示固定要求英文，中文视频和播客也会生成英文标题 | 标题和摘要按原字幕语言生成；中文使用简体中文，未知语言按正文判断 |
| 双语入口固定写 English | 非英文原文仍显示“English + 中文” | 英文保留原标签，其他语言显示“Original + 中文”；中文原文直接阅读 |
| 导入失败残留旧进度 | 后台失败后卡片仍可能显示“Transcribing segment…” | 失败时清除旧进度；书架优先显示导入错误状态 |
| 字幕延迟加载丢失搜索定位 | 首次返回没有字幕时，就消耗了 URL 中的段落定位 | 等字幕到达后定位；播放器尚未连接时暂存目标；阅读页内切换段落链接也会跳转 |
| B 站可用字幕被漏掉 | 实际 yt-dlp 返回内嵌 SRT，代码只接受 JSON，可能多做一次语音识别 | 同时接受内嵌 SRT 和原站 JSON；检查时间轴，保留字幕来源；忽略弹幕 |
| B 站分 P 缺少结果核对 | URL 保留了分 P，但解析后没有核对返回条目身份 | 核对提取结果的 BV 与分 P 标识；不匹配时拒绝继续 |
| 空书架提示仍只写 YouTube | 新用户提示只介绍 YouTube 链接 | 明确提示 YouTube、bilibili 和 Xiaoyuzhou |

播放器恢复跟随也已统一：播放和显式跳转会恢复跟随；打开笔记编辑时仍暂停跟随，关闭后继续。YouTube 播放器补入了与原生播放器相同的播放回调。

## 已确认可以共用的功能

以下功能按书架条目 ID 和账户归属工作，不依赖 YouTube ID。测试已覆盖三个平台：

| 功能 | 验证结果 |
| --- | --- |
| 手动状态与状态筛选 | Not started、Learning、Completed 可保存和恢复；书架卡片与筛选结果一致 |
| 标签与筛选组合 | 可添加标签，并同时按标签、状态搜索 |
| 划线、笔记和草稿 | 保留原文锚点；草稿可恢复；保存笔记后不会继续列为草稿 |
| 全库搜索与返回原文 | 搜索结果携带资料、段落与时间点；三个平台均可打开并定位播放器 |
| AI 问答与引用 | 使用该资料的原字幕和选段；引用对应真实段落；保存为笔记后保留原锚点与来源问题 |
| 章节导航 | 使用已保存的原站章节；没有章节时可按需生成 AI 章节 |
| 播放和字幕跟随 | 播放、跳转、手动浏览、笔记暂停与关闭后的恢复均通过回归 |
| 账户隔离 | 他人的状态、笔记、问答及媒体不能通过当前账户访问 |

## 仍有的平台差异

目前仍有以下差异，涉及播放、字幕来源和服务限制。

| 项目 | YouTube | 哔哩哔哩 / 小宇宙 |
| --- | --- | --- |
| 播放方式 | 官方 iframe 播放器 | B 站为本地缓存 MP4；小宇宙为音频播放器 |
| 导入期间播放 | iframe 可先播放，字幕另行加载 | 当前需完成字幕导入后才显示播放器；暂未提供边播放边等待转录 |
| 字幕轨道 | 可列出并切换多个可用轨道 | 当前导入时选择一个可用字幕轨道，或一个语音识别轨道 |
| 中文译文来源 | 优先尝试 YouTube 中文字幕，失败后使用 AI | 非中文原文使用 AI 翻译；中文原文不重复翻译 |
| 小宇宙逐字稿 | 不适用 | 尚未取得公开、带时间戳的逐字稿接口；目前通过音频识别，不把节目说明当作逐字稿 |
| 来源时长 | 当前最长四小时 | 当前最长两小时 |

`youtube_id` 仍是历史数据库字段名。新平台在该字段中保存带平台前缀的来源身份，去重不会把 B 站、小宇宙与 YouTube 混在一起；无需为了字段改名迁移既有笔记。

播放结束不会自动标记 Completed，三个平台都由用户手动决定是否完成学习。

## 验证与证据范围

- `npm run verify` 通过：86 项 TypeScript 测试、类型检查和生产构建。
- Python 测试通过：10 项媒体测试、5 项 YouTube 字幕测试。覆盖 yt-dlp 实际使用的内嵌 SRT 格式、JSON、自动字幕来源、无效时间轴和分 P 身份校验。
- Chrome 中通过 18 项跨平台状态与定位流程。B 站和小宇宙使用真实缓存媒体并实际解码播放；YouTube 使用已有真实字幕和后端，播放器 iframe API 使用模拟时钟，避免网络可用性影响状态测试。
- Chrome 中通过 12 项原生播放器字幕跟随流程，包括自然播放推进字幕、手动浏览暂停、播放与跳转恢复、清除未完成选择，以及笔记面板保持暂停。
- YouTube 通过 5 项笔记关闭回归：关闭新草稿、保存笔记后关闭、关闭编辑草稿、Escape、保存失败后的重试。
- AI 章节、问答和翻译使用模拟供应商响应，验证请求内容、语言要求、原文引用和数据保存；未新增付费 AI 调用。SRT 分支使用与已安装 yt-dlp 一致的输出格式测试，本次两个真实样例仍复用此前语音识别结果。
- 测试创建的笔记、草稿和标签已清理，测试前的状态与播放、阅读位置已恢复。两个已完成媒体任务保持缓存，没有再次转录。

本地字幕服务已重新加载修复后的解析器。刷新现有页面即可使用新版前端。
